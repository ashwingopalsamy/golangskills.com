# Evaluation harness

Every skill ships public development cases. The current corpus contains 87: every skill has a positive route, a confusion negative, and at least two quality scenarios. Quality cases name expected invariants, forbidden outcomes, deterministic graders, and optional semantic rubrics. Fifteen cases use executable fixtures for races, lifecycle completion, HTTP bodies, ambiguous commits, redelivery, retry amplification, API compatibility, fuzz regressions, rounding, ledger balance, payment ordering, settlement netting, configuration ownership, versioned-cache tombstones, and concurrent financial replay.

`skillctl eval run` creates one temporary project and ephemeral session per case. It installs no skills for baseline, the selected arm for treatment, randomizes order from a recorded seed, assigns an opaque arm label, records client/model/commit/grader metadata, captures raw runner JSONL, and resumes already completed cells. `-case skill-id/case-id` reruns an affected cell without restarting the arm.

`skillctl eval matrix` selects the same canonical cases for baseline, this project, and every frozen competitor, then globally randomizes all arm/case cells. Each arm receives a distinct deterministic opaque label. `-fixtures-only` selects all 15 executable cases; `-explicit` switches every arm to explicitly matched skills; and `-repetition N` makes repeat identity part of resumability. A mixed score artifact is reported with `-arm`; `-arm ours -against-arm gophers` performs an in-file paired comparison.

For this collection, a positive routing case expects its owning skill and a confusion-negative case accepts only its declared neighboring skill IDs. Competitor arms use a committed canonical-to-arm `-skill-map`; a case-specific `-routing-map` can override ambiguous mappings. Missing mappings fail closed. Baseline expects `NONE`. Isolated plugin namespace prefixes are normalized without weakening the expected skill ID. This separates arm-specific naming from prompt difficulty and prevents correct neighboring routes from being scored as false failures.

Fixture cells copy a locked failing Go module without its decisive tests into the isolated workspace and enable workspace edits. Only after the agent exits does the harness inject a read-only, repository-locked `_test.go` oracle, run an allowlisted offline `go test` target, and store the resulting Go sources, oracle, and grader output in raw JSONL. Validation rejects visible fixture tests, missing or unsafe oracle paths, and non-allowlisted targets. All 15 committed baselines fail their post-edit oracle. Explicit competitor cells require a frozen canonical-to-arm `-skill-map`; missing mappings fail closed.

`eval score` applies accepted-route equality and deterministic response/fixture graders. For non-executable quality cases, `-judge-model` adds a fresh, ephemeral Codex evaluator session per response and `-judgments` stores an append-only, resumable JSONL judgment artifact. The evaluator receives only an opaque candidate label, task, identity-redacted answer, invariants, and forbidden outcomes in globally randomized order. A strict output schema requires one Boolean and one evidence item per criterion. A compound invariant passes only when every clause is explicitly supported; topic mentions, promises to review later, and inferred requirements do not count. `skillctl` validates criterion counts, recomputes the total, binds the judgment to a digest of the source response and rubric, and fails closed on missing or invalid judgments. Runner success and executable oracles remain hard gates. Lexical response graders remain visible diagnostics but do not override a complete semantic verdict merely because a correct answer used different vocabulary. Reusing the same judgment path resumes successful cells while retaining failed attempts for audit and retry.

Codex judging Codex output is recorded as `same_platform: true`; it is blinded but not independent evaluation. The scorer stores the evaluator runner, model, client version, rubric version, evaluator-code commit, raw response, runner events, usage, source commit, and source digest. Judgment identity includes the schema and rubric versions, so a protocol upgrade cannot silently reuse older completions. No semantic result may support a release claim without those traceability fields. Run it explicitly:

```sh
go run ./cmd/skillctl eval score \
  -input evaluations/runs/quality-matrix.jsonl \
  -judgments evaluations/judgments/quality-matrix-codex.jsonl \
  -judge-model gpt-5.6-sol \
  -output evaluations/scores/quality-matrix-semantic.jsonl
```

`eval report` reports pass rate with a 95% Wilson interval, collection scores, routing macro-F1, unrelated-prompt false activation, client-reported token efficiency, and failures. With `-against`, it requires case-key pairing, assigns half credit to ties, bootstraps paired win-rate and mean-difference intervals, reports collection deltas, and classifies the score/input-token Pareto relation. A zero unrelated-case count means false-activation evidence is missing, not that the rate is zero. The harness does not turn keyword grading into a broad quality claim; executable fixtures and blinded rubrics are required for release evidence.

The first live semantic-judge smoke used one public fintech review case across seven native-discovery arms. All treatment cells and all seven current schema-v2 judgments completed without errors; an identical rerun wrote zero judgments. The first rubric version over-credited a response that merely named key reuse without requiring reconciliation. That attempt remains in the append-only artifact. Rubric v2 now requires explicit support for every conjunct, and judgment schema v2 binds the evaluator-code commit. Under the corrected protocol, ours scored 1.0; three arms scored 2/3 and three scored 1/3. This is operational evidence for blinding, resumption, source binding, and protocol correction—not comparative evidence: it is one public case, confidence intervals are meaningless, and the evaluator is same-platform. See the [raw responses](../evaluations/runs/2026-08-24-semantic-judge-smoke-native.jsonl), [judgments](../evaluations/judgments/2026-08-24-semantic-judge-smoke-native-codex.jsonl), [scores](../evaluations/scores/2026-08-24-semantic-judge-smoke-native.jsonl), and [ours report](../evaluations/reports/development/semantic-judge-smoke-ours.json).

The next three multi-file fixtures covered configuration alias ownership under the race detector, cache version/tombstone convergence, and concurrent financial replay with payload conflicts. Their untouched baselines failed the hidden oracles before the freeze at `66c0ba6`. The complete 21-cell native screen then passed all three cases for all seven arms with zero runner errors and zero cells written on identical reruns. These prompts and oracles are operationally valid but still saturated because they specify the complete target behavior. Explicit-mode repeats were skipped: after a 7/7 native tie they add cost without discrimination. The [raw and scored artifacts](../evaluations/runs/) and [development reports](../evaluations/reports/development/) are retained. Future deterministic cases must expose realistic symptoms and incomplete observability or crash schedules while testing only promised external behavior; adding more directly specified repairs is not useful.

The first production-shaped semantic case embedded an authorization/retry/webhook diff and seven criterion-level checks. It produced a genuine loss: `cxuu-golang-skills` scored 7/7; ours, baseline, `cc-skills-golang`, `go-skills`, and `golang-ddd-skills` scored 6/7; Gophers scored 5/7. Our response said the identity was bound to an immutable fingerprint but did not explicitly reject a reused identity with a different canonical payload. The rubric correctly withheld that invariant, and the paired report also showed `cxuu-golang-skills` using fewer input tokens. The review skill was then generalized to require equivalent replay, different-payload rejection before effect/disclosure, and wrong-authority nondisclosure. A separate ours-only post-fix regression scored 7/7. It is not substituted into the frozen matrix and does not establish transfer beyond this public case. See the [paired loss](../evaluations/reports/development/fintech-authorization-review-ours-vs-cxuu-golang-skills.json) and [post-fix report](../evaluations/reports/development/fintech-authorization-review-ours-postfix.json).

Two further production-shaped review cases were frozen together at `646d221` before treatment. The Engineering shutdown case completed all seven arms and all current judgments without errors: ours and every skill competitor scored 8/8, while baseline scored 7/8. Ours used 60,234 input tokens, so the quality win over baseline is a token trade-off and the skill-arm tie is not category separation. The Distributed Systems dual-write case also completed cleanly, but every arm scored 6/8. Our answer uniquely computed the 45-call publication envelope yet omitted explicit failed/unknown acknowledgement replay and did not assign retries to one owner with an end-to-end deadline and transient-error classification. At 78,155 input tokens, ours was also the most expensive arm on that cell. Identical treatment and judgment reruns wrote zero cells. Preserve these results as genuine evidence: the first case is largely saturated and the second exposes a reusable skill gap plus a token-efficiency failure, not superiority.

Commit `e6d69e1` added general effect-boundary and retry-accounting guidance, but two separate ours-only repetitions still scored 6/8. Runner traces prove the agent loaded the corrected review skill and its message-processing/data-consistency references. Both answers calculated 45 publication attempts and gave the transactional inbox/outbox repair, but neither explicitly resolved a failed/unknown consumer acknowledgement or completed the retry-owner/deadline/error-classification repair. This is negative regression evidence: adding correct prose did not make the behavior reliable, so a conditional final-answer completeness gate is required before another sample.

Commit `4486c17` promoted those obligations into a conditional completeness gate. Its first ours-only sample still scored 6/8: it newly selected a single bounded outbox-relay retry owner, but omitted the end-to-end deadline, transient-error classification, and explicit failed/unknown consumer-ack replay. The unchanged total also revealed that the last two rubric entries are compound and hide partial progress. Do not reinterpret the frozen comparison post hoc. Tighten the draft audit once for regression behavior, then use a newly precommitted production case with atomic criteria for transferable evidence.

Commit `57a70e2` added a final-prose audit rather than more domain rules. Five ours-only repetitions at that revision scored `1.0, 0.875, 1.0, 0.875, 1.0`: three complete passes, one missing explicit unknown-ack replay, and one missing the 45-call bound. Mean score was 0.95, but only three of five cells passed the all-criteria gate. This materially improves the original frozen 0.75 result while proving the behavior is still stochastic. Stop tuning on this public prompt. Retain all five raw responses and judgments; require transfer on a newly frozen case with one semantic fact per invariant.

The transfer case `review-go-distributed-change/quality-batch-offset-diff` uses a different schedule: cumulative partition offsets completed concurrently around an ambiguous non-idempotent remote effect, three retry layers, ignored offset-commit results, and a 100,000-message batch. Its first version was frozen at `1c5c1ca`, but adjudication invalidated the screen. The prompt says the remote call “retries at most twice internally,” meaning one initial attempt plus two retries; the rubric incorrectly required 24 total calls instead of `3 × 3 × 4 = 36`. Ours correctly calculated 36 but was marked wrong. Preserve all seven responses and judgments, but exclude every score and comparison from quality claims. Correct the invariant and lexical diagnostic in a new commit before rerunning all treatment arms. The separate missing `CommitOffset` repair remains a real omission.
