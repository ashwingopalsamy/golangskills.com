# Naming decision

The public identity is **Engineering Skills for Go**. The distribution slug is `engineering-skills-for-go`; the repository and future discovery site remain `golangskills.com`.

## Shortlist

| Name | Strength | Rejected risk |
| --- | --- | --- |
| Engineering Skills for Go | Says exactly what the collection improves; works with the domain; leaves room for more than prompts | Longer than a mascot name |
| Go Systems Skills | Strong production-systems signal | Can sound limited to distributed systems |
| Go Engineering Field Guide | Memorable and judgment-oriented | Suggests documentation more than executable agent skills |
| Go Production Skills | Clear operational focus | Understates design and review workflows |
| Golang Skills | Exact domain and strong search match | “Golang” is a search term rather than the language’s preferred name and can imply a generic directory |

GitHub repository-name searches on 2026-08-18 returned no matches for `engineering-skills-for-go`, `go-engineering-field-guide`, or `go-production-skills`; the broader `golang-skills` query returned 30 matches, including two supplied competitors. The configured Codex marketplace snapshots had no `engineering-skills-for-go` or `golangskills` plugin-name collision. These are time-bound discovery checks, not a trademark clearance.

`Gophers` was excluded because an established competing plugin already owns that identity. Names implying an official Go project were also excluded.

## Trademark posture

Public copy uses descriptive phrasing such as “skills for Go,” does not use the Go logo, and states that the project is independent and not endorsed by the Go project or Google. The domain remains useful for discovery without making `Golang` the product name.
